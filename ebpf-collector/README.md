# KernelWatch eBPF Collector

Kernel-side BPF programs + userspace daemon that stream live process/file/
network/injection activity as CDM20-shaped JSONL, so it plugs into the same
graph pipeline you're building for the DARPA TC data.

## Layout

```
bpf/collector.bpf.c    kernel-side programs (tracepoints, kprobes, LSM hooks)
include/collector.h     shared struct event schema
src/collector.c         userspace daemon: ring buffer consumer -> JSONL
src/collector.skel.h    generated by `bpftool gen skeleton` (build artifact)
Makefile
```

## Requirements (on your Ubuntu 24.04 dev VM)

```
sudo apt install clang llvm libbpf-dev linux-tools-$(uname -r) bpftool pkg-config
```

Kernel needs BTF enabled (`CONFIG_DEBUG_INFO_BTF=y`) — check with:
```
ls /sys/kernel/btf/vmlinux
```

Some hooks use LSM BPF programs (`SEC("lsm/...")`), which need
`CONFIG_BPF_LSM=y` and `bpf` listed in `/sys/kernel/security/lsm`. If your
kernel doesn't have BPF LSM enabled, swap `on_setuid`, `on_file_mprotect`,
and `on_unlink` for kprobe equivalents (`security_task_fix_setuid` etc. as
kprobes instead of `lsm/` attach points) — noted inline where relevant.

## Build

```
make
```

This dumps `vmlinux.h` from the running kernel's BTF, compiles the BPF
object, generates the skeleton header, and links the daemon.

## Run

```
sudo ./collector                  # JSONL to stdout
sudo ./collector -o events.jsonl  # JSONL to a file, append mode
```

Ctrl-C to stop; both SIGINT and SIGTERM are handled for a clean detach.

## Output shape

Every event emits a `RECORD_SUBJECT` line (the acting process) followed by
a `RECORD_EVENT` line (the typed edge), matching the two record kinds your
CDM parser already consumes. Example:

```json
{"type":"RECORD_SUBJECT","uuid":"a1b2c3d4e5f60789","pid":534051,"ppid":533998,"tid":534051,"uid":1003,"euid":1003,"gid":1003,"egid":1003,"comm":"firefox","start_ns":1557946074138739955}
{"type":"RECORD_EVENT","event_type":"EVENT_CONNECT","timestampNanos":1557946074138739955,"subject_uuid":"a1b2c3d4e5f60789","object_uuid":"9f8e7d6c5b4a3210","object_type":"NetFlowObject","localAddress":"128.55.12.110","localPort":40837,"remoteAddress":"208.203.20.42","remotePort":80}
```

## Notes / next steps

- `EVENT_READ`/`EVENT_WRITE`/`EVENT_MMAP` hooks are intentionally left out
  of the first pass (see the design doc) — they're the highest-volume,
  lowest-signal events and will flood the ring buffer if enabled before
  everything else is validated. Add `vfs_read`/`vfs_write` kprobes once the
  rest is stable, with an fd->file_uuid map populated at `EVENT_OPEN` time.
- `EVENT_INJECT_PTRACE` / `EVENT_INJECT_VM_WRITE` are not part of CDM20 —
  they're added specifically to catch the process-injection technique used
  in the DARPA TC Engagement 5 THEIA scenario (Firefox -> elevate -> ptrace
  or vm_writev into sshd), which CDM-based collectors never captured.
- UUIDs are FNV-1a hashes of (pid, start_ns) for subjects and
  (addr/path) for objects — deterministic, not cryptographically unique,
  good enough for graph node identity within one collection session.
